## Lecture

- **Statut** : `masque` = le numéro ne sort pas ; `non-verifie` = il sort ; `verifie` = posé par le projet seul.
- **Vu à l'exécution** : nombre d'émissions et contextes d'affichage (`terminal`, `journal`, `dialogue`, `navigateur`, `trace`) relevés pendant la batterie complète. « — » = jamais vu : le code existe dans le source mais aucun test ne l'a fait sortir.
- **Pannes** : pannes dont la définition (ticket, cause, indices, correction) cite le code. Ce n'est PAS la liste des pannes qui le font afficher : un code produit par le moteur (par exemple une ligne de journal IOS) peut apparaître dans des pannes que cette colonne ne nomme pas. Colonne **à compléter** par exécution panne par panne (travail non fait).
- **Origine** : pour tous, « mémoire de l'auteur du code, aucune source jointe ». Aucune capture ni documentation officielle n'est rattachée à ces valeurs dans le dépôt.

## Ce que cet inventaire ne dit pas

- **Les Event ID ne sont pas dans le source sous forme de texte** : ils passent par le journal (`WIN.evt`, `AD.evSec`). Leur ligne « Écrit dans » vient du registre, pas du balayage. Dix identifiants sont enregistrés : 1046, 1063, 1502 (masqués), 1058, 1129, 4624, 4625, 4740, 4771, 7036 (non vérifiés).
- **Codes dans les textes de contenu** (ticket, cause, solution, indices, chemin optimal) : ces textes ne passent pas par le point d'émission unique. Exemple : l'événement 1046 est masqué dans le journal mais cité dans la cause et le chemin optimal de `dhcp_unauth` et de `dhcp_unauth_bdx`. Écart à trancher par le projet (proposition dans `DECISIONS-PROPOSEES.md`).
- **Valeurs numériques sans forme reconnue** (code d'échec Kerberos `0x25`, `0x18`, `Statut : …` des événements 4625) : hors des familles que le mécanisme sait reconnaître. À traiter avec le projet.
- **Sous-statuts d'authentification** (ex. `0xC000006A`) sont des NTSTATUS : ils sont inscrits au registre, mais leur sens dans un événement 4625 attend une source.
